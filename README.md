# B19LP — B19 landing page

**https://b19studio.net**: a portfolio of recording, mixing and mastering work by Jędrzej Wencka (B19 Audio Production). English at `/`, Polish at `/pl/`, plus privacy and accessibility pages in both languages. It is plain HTML, CSS and JS, with the pages generated by a small Python script.

## Commands

The same `site.sh` is in every landing-page repo. Only `site.env` (names, domain, build command, preview port) differs.

| Command | What it does |
| --- | --- |
| `./site.sh build` | build the site into `dist/` |
| `./site.sh serve` | build, then open it on http://localhost:8000 |
| `./site.sh preview` | publish a copy hidden from Google on http://2.28.230.117:8083/ |
| `./site.sh deploy` | publish to production (asks first; `--yes` skips the question) |
| `./site.sh rollback` | put the previous production files back (the last 3 are kept on the server) |
| `./site.sh status` | container state and HTTP status on the server |

You need SSH key access to `root@2.28.230.117`, plus `rsync` and `python3` (both come with macOS). To use a different server, run `HETZNER_HOST=user@host ./site.sh …`.

Every build checks itself before anything is uploaded. A production build must not contain `noindex` and must have a canonical link. A preview build must contain `noindex`.

## Structure

```
site.sh / site.env           build + deploy (see Commands)
src/index.template.html      page layout with {{placeholders}}. EDIT THIS
src/i18n.json                all texts, en + pl
src/legal.template.html      privacy / accessibility page layout
src/privacy.json, src/accessibility.json   their texts (paths set inside)
src/gallery.json             studio gallery
tools/build.py               template + texts -> dist/ pages, sitemap.xml, robots.txt
site/                        static files copied into dist/: css/, js/, assets/, audio/ (not in git)
site/js/work-data.js         ← portfolio list, edit this to add work
site/js/main.js              animations, player (button labels at the top)
site/js/peaks.js             waveforms for the self-hosted tracks
site/js/consent.js           cookie consent
deploy/nginx.conf            nginx inside the site's container
docker-compose.yml           the container (same file in every landing repo)
compose.preview.yml          adds the public port for ./site.sh preview
dist/                        build output, not in git
```

The pages (`/`, `/pl/`, `/privacy/`, `/pl/prywatnosc/`, `/accessibility/`, `/pl/dostepnosc/`) exist only in `dist/` after a build, so don't look for them in `site/`. The `?v=` number on CSS and JS links is bumped on every build, so browsers pick up changes straight away.

## Add portfolio work

Edit `site/js/work-data.js`. Each entry has `artist`, `title`, `roles` (`prod`/`rec`/`mix`/`master`), `genre`, `year`, and either:

- `audio`: a file in `site/audio/`, played in the B19 player, or
- `link`: a Spotify, YouTube or SoundCloud link, played in an embed.

## Audio files

Self-hosted tracks live in `site/audio/` as `<name>.mp3` (320 kbps, the default stream) and `<name>.flac` (24-bit lossless, used by the "LOSSLESS" switch). Their waveforms come from `site/js/peaks.js`.

`site/audio/` is **not in git**: it is large, and the repo is public while the masters stay private. `./site.sh deploy` uploads only new or changed audio files and never deletes audio on the server.

## Deploy

```
./site.sh preview    # http://2.28.230.117:8083/ (hidden from Google)
./site.sh deploy     # https://b19studio.net
```

**First deploy after the switch to `site.sh`.** Until November 2026 the server ran a git clone in `/opt/b19lp` (`git pull` + `deploy/update.sh`), and `ww-landing` had a hand-written block for b19studio.net. The first `./site.sh deploy` does the move by itself:

1. It creates `/opt/b19-landing`, starting from a copy of `/opt/b19lp/site` so the audio is not uploaded again.
2. It replaces the old `b19-landing` container. The name stays the same, so nothing else changes.
3. It replaces the old proxy block with the managed one.

The server no longer uses git. Once the new setup looks fine, you can delete `/opt/b19lp`.

## Server (shared by all the sites)

The sites run on Hetzner at `2.28.230.117`. One nginx container, **`ww-landing`**, owns ports 80/443 and handles HTTPS (Let's Encrypt). Every other site runs in its own small nginx container with no public port. `ww-landing` forwards each domain to that container by name, over the Docker network `ww_landing_default`. Preview copies are published on their own port and are hidden from search engines.

| Site | Repo | Production | Container · server folder | Preview |
| --- | --- | --- | --- | --- |
| Whitewater | `ww_landing_v2` | https://whitewaterband.com | `ww-landing` (the edge itself) · `/opt/ww_landing/dist` | `:8081` |
| Supernova | `supernova-site` | not yet (supernovaband.eu) | `supernova-site` · `/opt/supernova-site` | `:8080` |
| Impala | `impala-site` | https://impalaband.com | `impala-site` · `/opt/impala-site` | `:8082` |
| B19 | `B19LP` | https://b19studio.net | `b19-landing` · `/opt/b19-landing` | `:8083` |
| Spotify player | `SpotOnlinePlayer` | private (`127.0.0.1:8787` on the server) | `spotify-cloud-player` · `/opt/spotify-cloud-player` | — |

- Each site folder on the server holds `html/` (the files), `nginx/default.conf`, `docker-compose.yml` and an `.env` written by `site.sh`. Before every upload, a snapshot of the live files is saved as `html.bak-<date>`. These are hard links, so they cost no disk space.
- The edge config is `/opt/ww_landing/nginx.conf`. `./site.sh deploy` keeps each domain's block there between `# >>> <name>` and `# <<< <name>` markers. It only rewrites a block that has changed, backs up the file first, and restores it if nginx rejects the new config. It never touches another site's block. On the first deploy of a new domain it also gets the HTTPS certificate. Certbot renews certificates automatically and reloads `ww-landing` afterwards.
- Preview ports may need to be opened in the Hetzner Cloud firewall.
